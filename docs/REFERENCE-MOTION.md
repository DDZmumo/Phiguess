## 第九章难度选择参考

四段输入均位于用户指定的 `D:/Program Files/JiJiDown/Download/`，规格为 1440×1080、30fps、17.4 秒，每段 522 帧。原视频未修改；共 2088 帧的分析副本位于 `storage/references/difficulty/{at,in,hd,ez}/frames/`。来源索引为 `sources.json`，逐帧亮度数据为 `*-metrics.json`，总览为 `*-overview.jpg`。可用 `tools/analyze-difficulty-reference.py --full` 重建分析产物。

四片共有反相帧区间：74～76、79～80、86～94、417～419、422～423、429～434、436～454；最终黑场从第 456 帧（15.2 秒）开始。这些帧点直接用于网页时钟；静止选择对应参考片约 0.5 秒的状态，点击后继续播放约 14.7 秒。0.8～1.55 秒选中项居中，2.1～3 秒括号拉开，约 3.5～6.08 秒停留，6.08 秒后加速滚动，10 秒后逐渐增强纵向拖影，12 秒后过渡到全高条带，最后闪烁并进入黑场。

大数字按要求替换为 Heavy 中文，最终逻辑字号为 216px。逐帧复查发现，先前 2.15 秒开始的 60%→100% 放大不符合原片：原片首个可见大字在第 75 帧，模板测得第 75、77、82 帧投影比例分别约为 0.70、0.87、1.00，之后字号稳定。实现已去掉那段额外放大曲线，只保留这些源帧中的短暂投影变化；左右入场位移分别使用测量数据插值，约第 110 帧停稳。滚动在第 167 帧前后开始；167～280 帧使用逐帧相关跟踪的左右累计位移，转轮行距为 400 逻辑像素，右列更快。270 个不同汉字按转轮行号随机接续。

早期实现曾使用原片透明图集。当前小标签由 `difficulty-painter.ts` 的 `liveLabels` 实时绘制，位置与透明度使用参考测量数据，光晕由 `difficulty-atlas.ts` 在运行时生成并缓存；不加载 `labels-*.webp`。原片第 74、76、94、417、419 帧为近乎纯色的闪帧，单独按采样颜色显示，不能仅用反色替代。开发对照页支持四档选择、左右逐帧、慢放和叠加，原片与网页均显示零起始参考帧号。全部 2088 帧的测量和绘制副本位于 `output/playwright/difficulty-frame-review/`。

运动在源帧之间连续插值，上限 120fps 更新，故障与反相按参考 30fps 的帧区间触发。汉字字形和故障 shader 为浏览器重绘；被故障遮挡的字形位置采用邻帧插值，280 帧后的强拖影速度仍是锚点拟合。以上边界不应被描述为原视频逐像素、每帧完全一致。保留返回按钮、键盘焦点及减少动态效果适配。

当前绘制混合使用实时清晰文字和运行时共享纹理：`sharpGlyph` 与 `liveLabels` 使用 `fillText`，运动模糊、重模糊、最终条带和标签光晕复用缓存，强模糊列先在小缓冲中合成；画外、透明行不绘制。下列帧率数据保留为历史优化验收，不能推导当前所有帧都只组合纹理。2026-10-09 最终 HD 实局在 1920×1080 浏览器下采到 1675 次绘制更新（参考帧 30～449），约 120 次/秒；后段 300～449 帧采到 600 次更新，间隔 P95 为 12.3ms、最大 12.7ms。这是本机 Canvas 调用节奏，不是显示器实际呈现帧率或跨设备保证。只创建一次比赛；390×844 下四个选项均在视口内，EZ 中途 Esc 返回未创建比赛，构建通过、浏览器无错误。关键帧对照为 `output/playwright/difficulty-calibrated-comparison-final.png`，采样摘要为 `output/difficulty-performance/final-cadence.json`。

本轮验证：四个映射均已在浏览器显示；三次中途返回均未创建比赛；完整 HD 动画约 14.88 秒后仅发送一次创建请求，随后保留约 3 秒准备时间和完整 15 秒答题时限；减少动态效果下创建 IN 房间参数正确。390×844 竖屏四个选项全部处于视口内。对照截图位于 `output/playwright/difficulty-*.png`，前端构建通过，浏览器无错误。

## 动画测量与实现

- 进入游戏：亮度采样在约 13.325 秒出现明显下降，13.708 秒达到黑场，14.017 秒重新出现非零亮度，约 14.7 秒完成淡入。实现为约 400ms 淡出、300ms 黑场停留、700ms 新场景淡入，并按亮度采样拟合 opacity 曲线。用户要求替换目的地，因此直接淡入账号页；视频没有账号页的进入动画样本。
- 选曲：对 3.533～4.333 秒的 `Spotlight` 标签做相关匹配，分析图尺度 605×417 上 y 从 207 移至 239，x 从 51 移至约 42；折算重建尺度，单步向下约 64px、向左约 18px。
- 源片段存在小幅过冲：标签最高到 y=242，随后回到 y=239。GSAP CustomEase 使用这些采样锚点插值，800ms 内移动和回落；不是默认的通用 ease-out。
- 列表按最新截图修正：普通行节距 64px，选中行上/下额外让出 10.25/13.25px。每行分别沿 15° 轨道运动，编号底板固定，文字缩进同步过渡。本局范围外不添加乱码占位行；按用户要求不复制成绩标识，右侧继续显示猜歌序号。
- 图片采用上下连续两层，旧图向下移出，新图从上方移入。只在新回合授权并解码完成后，与列表运动在同一 React 更新中触发。图片曲线根据可见进入区域近似拟合。当前允许预取下一题密文，明文解密密钥仍须等到该题开始才提供。
- 使用 `useGSAP` / scope / cleanup 管理时间线；普通按键不做大幅弹跳。减少动态效果设置和系统偏好均会停止列表位移，仅保留短淡变。
- 答对歌名遮盖采用两段 `power3.inOut`：220ms 从左端伸长，完全覆盖后替换文字，200ms 保持左边界向右运动直至歌名末尾。覆盖期间冻结乱码，减少动态效果时直接显示曲名。
- 答对揭晓曲绘后留出观察时间：全员猜中或超时后均保留 2 秒；下一题直接开题，不重复 3 秒倒计时。首次进入的准备时间及每题完整时限保持不变。

## 难度居中后的挑战设置

主页移除了题数和时限选择。单人选定难度后，时间轴先运行到参考 2.0 秒（第 60 帧），此时字母居中，括号及大字尚未展开。时间轴在这里停住，挑战设置文字以 0.65 秒淡入；确认后用 0.45 秒淡出，完成后才从第 60 帧继续原转场。比赛创建仍在转场结束之后，设置停留不会消耗答题时间。

EZ 强制关闭 HP；普通 HD／IN 可选关闭、20 或 50，IN Infinity 与 AT 强制 20/50。服务器按开局难度与模式归一化，并保存 `matches.health_enabled`、`health_capacity`，不随降图提示改变。保留的房间实现可在房间内配置，不经过单人剧情难度转场；当前主界面多人入口处于维护关闭状态，不能视为已开放的 UI 流程。
