# 设计与边界

## 单机部署

目标单机部署拓扑面向 2 核 10GB、10Mbps、云服务商 NAT 转发环境：一个常驻 NestJS 实例和 PostgreSQL，由 Caddy 统一代理；这不代表本次文档更新已完成线上部署。生产数据库连接池上限为 5。当前不实现横向扩容、房间迁移或 Redis 广播。

服务通过模块分离身份、曲库、比赛、房间和实时协议。比赛的所有内存变更串行处理；持久化答题和分数使用同一个数据库事务。`guesses` 对“用户、请求 ID”唯一，并对“比赛、回合、用户”的正确记录设置部分唯一索引。允许多次错误尝试，但同题只能成功计分一次。

运行中房间与回合调度在内存，用户、会话、题目版本、所有提交和分数在 PostgreSQL。启动时将数据库内残留的 `active` 比赛标为 `interrupted`。中断场次保留历史，不进入排行榜，玩家可重新开局。账号主界面通过 `/me/active` 查询正在进行的比赛，有比赛时禁用开始按钮并显示继续按钮。

完成的比赛快照在内存保留约一小时，之后可读取持久化结果，也可恢复已结束场次最后一题的快照与授权题图。恢复快照统一显示 `finished`，数据库仍保留 `finished/interrupted` 的真实结果状态。服务端上限 100 个同时活跃比赛、200 个房间只是资源保护阈值，不代表经过压测的容量承诺。

## 素材和公平性

导入器只读取 Raw 与 EZ，为高难度建立指向 EZ 的元数据。HD/IN/AT 在独立工作线程中按持久种子生成，同题主图与降档提示共用分区；开局先生成最多 10 组，首题下载解码后才计时；随后补足包含当前题的 20 道待答题。生成缓存可回收，历史结算可按配方重建，详见 [实时题图](DYNAMIC-ARTWORK.md)。Raw 原图另做公开背景预览。

房间与练习开局时确定题组，不对客户端暴露未来题目或素材 ID。每日挑战已移除，历史数据库表只作存档保留。

正式计时开始后才允许下载当前明文题图。当前题开始后可以预取下一题经过 gzip 与 AES-256-GCM 加密的数据，密钥只在下一题正式开始后的快照中提供；不能提前取得下一题明文。计分按服务器收到答案的时间计算，图片下载/解密/解码延迟仍会影响体验，不构成竞技级网络公平。后续若做严肃排位，需要重新评估加载与计时规则，并使用真实 NAT 网络实测。

当前规则为 `v5-hint85`：每题满分 EZ/HD/IN/AT 为 500/1000/2000/3000，前 1/6 时限不扣时间分，之后线性最多扣 50%；每次错答再扣满分 10%，最多扣 50%。前两条提示不降低计分上限；第三条“得分减少，难度下降”将题图降低一档，实际计分上限改为原满分的 85%，但题目应得满分和综合牌分母保持开局难度。新规则只用于新对局，旧记录不重算，旧规则成绩在同一榜单显示“--”，不参与新规则排名。所有人猜中或归零、超时、单人跳题可结束当前回合；通常揭晓停留 2 秒再换题，首题保留 3 秒准备，后续题不重复准备倒计时。

HP 已接入服务器持久化与结束条件：EZ 关闭，普通 HD/IN 可选 0/20/50，IN Infinity 与 AT 强制 20/50。开启时满血开局；错答 -1，超时/跳题再扣 `max(3, 5-本题错答次数)`，答对按提示 0/1/2/3 次回 5/3/2/1HP，噪域命中 -1 且不计入错答次数。全体玩家耗尽 HP 会结束比赛；多人场一人归零不等于全场结束。噪域请求带幂等 ID，服务器验证阶段和资格，但不验证客户端坐标是否命中噪域像素。

Infinity 是开局时对可用歌曲去重后的一次遍历，走完曲库或全员耗尽 HP 即结束。排行榜仅纳入用户主动发布的、当前规则下已完成的单人 IN/AT Infinity 成绩，按难度、HP 上限和时限分组，每人取最佳，同分同名次。榜单还包含标记为 `isReference` 的静态参考角色，不是实际玩家战绩。

## 当前产品范围

- 支持游客和用户名/密码账号；`/auth/login` 对新用户名自动注册，对已有用户名验证密码。会话有效期为 30 天，密码用加盐 scrypt，token 仅保存哈希；尚无密码找回、第三方登录或防多账号刷榜机制。
- 已有视频参考驱动的前端、界面转场、可选的短提示音和用户提供的实际曲库；没有管理员网页、匹配系统、赛季段位或聊天。
- 没有在线模型调用、服务器描摹或自动难度评估。已支持本人答对后读取 Raw 预览，以及场次结束/中断后由参赛者揭晓错题原图；公开 showcase 另用于背景展示。接口权限不等同于原图内容全站保密。
- SVG 校验采用严格子集；文件中的 id 仍需由素材审核保证不包含答案。自动描摹效果和真实难度需要人工验收。
- 日志记录基础服务错误；尚无外部监控告警、自动备份平台或生产负载基线。

## 前端接入

`apps/web` 使用 React + Vite，复用 `packages/contracts`。HTTP 负责操作，Socket.IO 负责完整状态快照；每 10 秒补取快照以处理遗漏，重连重新订阅。动画系统独立于比赛状态，即使降低动效或手机掉帧也不影响计分。

手机仍以横屏为主，保留已有布局与 834px 高度参考画布的等比缩放规则。`use-app-viewport.ts` 结合容器、Visual Viewport 和输入焦点测量可见区域，`mobile-viewport.ts` 区分旋转、工具栏变化和键盘遮挡。键盘打开时保留画布尺寸，在独立的可见视口中滚动至输入框，关闭后恢复视口；排名、歌曲轨道、曲绘与输入栏的相对位置不改变。`mobile.css` 仅处理安全区、全屏按钮隐藏、透明触控扩展和浏览器交互，不覆盖原有视觉尺寸与位置。噪域共享舞台在页面隐藏或原生弹窗打开时停止帧循环，恢复后读取最新时间；无效区域不进行布局读取和纹理准备。

单人入口与“开始挑战”先进入 `/difficulty`，旧的账号页四按钮选择器已移除。`DifficultySelect` 用原生按钮提供选择与键盘访问，`DifficultyPainter` 在 Canvas 内重绘发光标签、双列汉字转轮、条带拖影和故障闪烁；GSAP 驱动连续时钟，绘制更新上限为 120fps，反相与故障帧仍对齐原片的 30fps 帧点。AT/IN/HD/EZ 的大数字改为“外挂/龙比/人类/区区”，使用 85,372 字节的 Heavy 汉字子集。

滚动字符池有 270 个不同汉字；每次进入生成独立随机种子，按列与行确定字符，使相邻文字连续接续，而非逐帧替换整列。左右滚动曲线分别按参考片拟合，右列更快。`difficulty-atlas.ts` 在浏览器运行时生成并共享字形、纵向模糊、条带与标签光晕缓存；`difficulty-painter.ts` 混合绘制实时清晰文字与缓存纹理，跳过画外与不可见行。清晰汉字、大字和小标签仍通过 `fillText` 绘制，不能描述为全程不实时描字。强模糊阶段先在每列的小缓冲中合成，再绘制到主画布；主画布像素数上限为 1920×1080，DPR 上限 1.5。

逐帧校准数据为 `difficulty-reference.json`。大字从参考第 75 帧进入，取消原先提前到 2.15 秒、持续 0.95 秒的估计放大；仅第 75～82 帧使用原片测得的短暂投影比例，之后保持稳定字号。入场位置来自可辨认帧的模板匹配，闪烁遮挡的间隙插值补齐；第 167～280 帧的左右上移量来自逐帧相关跟踪。第 280 帧之后强拖影中的速度仍使用尾段锚点，不能把该阶段声称为精确速度测量。

小标签由 `difficulty-painter.ts` 的 `liveLabels` 实时绘制 Saira 字符，光晕来自 `difficulty-atlas.ts` 运行时生成的 `labelGlows`；不依赖不存在的 `public/difficulty/labels-*.webp`。位置与透明度由 `difficulty-motion.ts` 和参考测量数据驱动，整屏闪帧按原片帧点触发。`tools/package-difficulty-motion.py` 是保留的历史素材处理工具，不是当前页面的构建依赖；测量与开发对照工具位于 `tools/measure-difficulty-*.py`、`tools/difficulty-frame-review.html`。

选择后播放约 14.7 秒的有效动画（参考片 0.5～15.2 秒），最终黑场才创建比赛，保证完整的准备与答题时限。返回或 Esc 取消不创建比赛；在减少动态效果模式下跳过滚动与闪烁。当前 `Hub` 的多人入口由 `MULTIPLAYER_ENABLED=false` 关闭，`/difficulty/room` 会回到账号页；房间服务、HTTP/Socket.IO 接口与部分前端实现仍保留，不能据此声称当前 UI 可创建/加入房间。

标题页点击进入后到账号主界面，顶部导航为“游戏 / 排行榜 / 设置”。“游戏”汇集玩家资料与模式入口，挑战参数在难度页配置，资料仍通过卡片的编辑按钮操作。游戏采用课题模式选曲布局：左侧为题目轨道，右侧为题图；难度只显示当前图片档位，灰条输入歌名，Select 位置提交。文字输入框聚焦时不显示蓝色外框，歌名框仅保留淡色下划线。提示直接显示在方框内，依次为章节范围、身份信息、降低一档图片；EZ 去掉降图项，只保留两个框。身份信息在 EZ/HD 为章节与曲师，在 IN/AT 为曲师与该曲绘画师。API index 顺序为 `[0, 2, 1]`（EZ `[0, 2]`），不是数字顺序。左侧由当前玩家自己的作答进度驱动，不暴露其他玩家的输入。

`HintStrip` 为纯展示组件：只能通过左上角“提示”按顺序解锁，框内没有按钮或点击处理。未解锁时仅显示 1st/2nd/3rd，解锁后只显示提示内容，没有编号、辅助小字和滚动条；内容根据框内空间换行、适配字号。

题图用 Bearer 请求后创建 Blob URL，保留相邻两张完成上下换图，释放旧 URL。允许提前缓存下一题密文，但新回合开始前没有密钥，不能解码明文；图片解码后才同步触发列表位移与曲绘运动。真实加载耗时仍会影响看到题图的时刻。

题图以 `object-fit: cover` 保持原比例铺满斜切框，边缘按框裁切。点击曲绘可在浏览器中央查看完整放大图，复用已授权的同一 Blob URL；Esc、关闭按钮或点击空白处返回。查看期间不暂停比赛，换题或图像难度变化会关闭查看层。原生 dialog 管理焦点与键盘退出。

猜歌页曲绘与作答区域保留原版构成，由 `game-alignment.css` 校准斜边；左侧整栏单独重写为 `SongRail.tsx` / `song-rail.css`，不再使用旧 `.track-*` 样式。曲绘切角按高度乘 tan(15°) 计算，输入栏、提示栏沿同一组斜线延伸。提示仍直接显示在框内，EZ 两提示、限时多次回答与计分规则保留；仅首题保留准备倒计时。

歌曲列表仅渲染本局题目。整栏共享 640×834 的局部坐标，工具栏与列表一起响应窗口宽度。背景平面、选中黑条与白块用独立 SVG 多边形绘制，文字用正直 HTML 排列：背景顶边从 x=193 延伸到 613.75，15% 黑色遮罩；选中条遮罩为 54%，不再让整栏变成深黑渐变。普通行 64px 节距，选中条高 90.5px，白块高 99px，上/下突出 4.5/4px。相邻上/下行额外让出 10.25/13.25px，沿 15° 轨道平滑移动。选中歌名 34.5px、普通歌名 22.5px；保留猜歌序号，不复制成绩标识。恢复挑战直接定位当前题。

未知歌名以 40ms 间隔更新与答案无关的字母、数字、符号和方块，文字区域尺寸固定；页面隐藏或减少动态效果时暂停。`SongName` 在答对后冻结乱码，以 220ms 非线性长条从左向右覆盖，完全覆盖时替换成真实曲名，再用 200ms 从左向右收拢到曲名末尾。已揭示曲名保持稳定，比赛时限与快速换题不受动画控制。

游戏、房间和结算共用的右上玩家框采用 `player-chip.css`：只裁切背景形状，头像和昵称不做斜切变换，并留出右边距。长昵称省略显示，上传头像以正方形区域正常渲染，避免父子反斜切叠加后被整个外框截断。

启动页和账号资料面板共用一次刷新随机选择的 Raw 原图预览，刷新时排除上一次图片。背景选择不影响题目抽样，也不返回歌名。题图降级独立记录在玩家与回合上，图片接口只返回该玩家解锁到的版本，重连可恢复。

账号界面只绘制一张铺满页面的背景图，并只保留一张斜切资料卡，包含可上传头像、昵称、玩家 ID、编辑与登出。资料卡内不再显示成绩统计，也不为此请求历史成绩接口；排行榜和比赛结算仍保留。卡外采用模糊与压暗遮罩，卡内是遮罩上的清晰窗口，透出同一背景对应区域，不单独铺图。窗口裁切随资料卡与窗口尺寸更新。

模式入口位于账号主界面，题数、时限与 HP 参数在 `DifficultySelect` 的居中暂停阶段配置，确认后继续转场。继续按钮仍在开始按钮下方；有进行中挑战时开始按钮禁用。账号页专用样式位于 `apps/web/src/account.css`，避免影响猜图界面。

同一歌曲可有多个 `variant`。题目抽样先按 `song_id` 分组，每组挑一个曲绘版本，再选本局歌曲。所有曲绘版本共享标准曲名与别名，不将同一首歌的四种原曲绘当作四首歌。

## 结算图片缓存与预载

结算图片加载复用猜题时已经取得的题图文件，按账号、比赛、题号和显示难度隔离；降档提示图不会冒充开局难度的结算题图。题图文件缓存上限 16 MiB，按进入顺序淘汰；原图仍使用 32 MiB 解码估算缓存。退出该局结算或切换账号时清理缓存，已挂载图片的引用在组件卸载时释放，因此这些缓存上限不等于整个页面内存上限。

结算提前加载上下约两屏的图片，首次加载后保留到退出。下载队列最多同时执行两个请求，当前屏幕优先于附近图片，未猜中的原图按题号后台顺序预载；后台工作最多占一个传输位置。滚动进入可视区域会提升尚未开始的请求优先级，不取消已进行的共享传输。历史结算或缓存淘汰后的图片仍可能需要下载。

## 噪域渲染预算

曲绘、曲名和提交按钮共用一个噪域渲染器。`noise-render-policy.ts` 为粗指针且无悬停的设备提供 60fps 图层更新预算、1 倍 DPR 与 960×540 总像素上限；桌面同样以 60fps 为目标，最高 1.5 倍 DPR 与 1920×1080 总像素上限。预算同时限制各层的 DOM 读取、源图绘制和最终合成，避免高刷新率下先反复更新图层再丢弃绘制。

共享调度器将实际刷新间隔送入自适应分辨率逻辑，持续掉帧时沿 1／0.82／0.67／0.55／0.45／0.35 六档降低噪域缓冲尺寸，合成源纹理同步缩小；运行恢复稳定后逐档提高画质。超过目标间隔 20% 的帧参与掉帧统计，严重卡顿也能触发降画质。CSS 布局、逻辑坐标、噪域生成时刻和服务端计时不随画质改变；红区仍使用同一 shader 做精确命中。

手机和桌面共用绘制范围优化：shader 按当前有效区域数量循环；透明噪域层仅在区域、外缘和渐隐交互光效的包围范围内绘制，并清除旧覆盖，避免范围收缩时留下残影。原图背景演示继续绘制完整画面，命中检测使用独立的 1 像素缓冲。模拟中的渲染工作量减少不等同于实际设备的帧率提升，真机体验仍需在对应设备上确认。

## 本地互动教程

`/tutorial` 为 16 步本地练习，直接挂载正式的 `DifficultySelect`、`Game` 和 `Results`，由 `PlayRuntimeContext` 注入 `TutorialRuntime` 管理教学请求、快照、受控时钟、图片和导航；不使用全局 fetch 拦截，也不替换正式用户身份。主界面玩家资料卡提供教程入口；不创建真实比赛，不提交答案、成绩、噪域或房间写请求，也不覆盖既有比赛与用户偏好。`Tutorial.tsx` 负责步骤、底部居中字幕的淡入淡出与收缩闪烁圆圈，`TutorialScoreRules.tsx` 在现有结算上分 7 段居中展示计分说明和真实牌子，不更换结果 ID 或重播结算入场，`TutorialEndTransition.tsx` 在黑屏中显示结束文字并自动淡出返回主界面。教学依次使用 DS、米垃圾、超市入口和 8000 的真实四档素材及原图，别名与提示直接取自本地曲库，讲解阶段暂停教学时钟，闪烁演示时再推进；教学将正式的 0.8 秒闪烁慢放至 2 秒，正式规则保持不变。教学 HP 为上限 20、初始 12，以展示完整回血变化。操作完成后的延时推进与计分演示段落计时均由运行时管理，页面不可见时暂停。刷新时从当前标签页的 sessionStorage 临时快照恢复步骤、比赛状态、草稿、结算揭晓、滚动位置和讲解段落；页面动画、焦点与待处理 Promise 重新建立，已结算操作不重复执行。临时快照在挂载后或主动退出时清除，新访问（包括关闭后重新打开教程网址）直接返回主界面，不使用长期进度存档。教学成绩和示例复用 `game-core` 的正式计分与成绩牌算法；第三提示只改变显示图片难度，计分档位仍是开局档位。

详细请求边界、提示索引与结算揭晓权限见 [API.md](API.md)，素材统计口径与本地重建前提见 [ASSETS.md](ASSETS.md)。
