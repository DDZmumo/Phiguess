# 设计与边界

## 单机部署

针对当前 2 核 10GB、10Mbps、云服务商 NAT 转发环境，使用一个常驻 NestJS 实例和 PostgreSQL，Caddy 统一代理。生产数据库连接池上限为 5。当前不实现横向扩容、房间迁移或 Redis 广播。

服务通过模块分离身份、曲库、比赛、房间和实时协议。比赛的所有内存变更串行处理；持久化答题和分数使用同一个数据库事务。`guesses` 对“用户、请求 ID”唯一，并对“比赛、回合、用户”的正确记录设置部分唯一索引。允许多次错误尝试，但同题只能成功计分一次。

运行中房间与回合调度在内存，用户、会话、题目版本、所有提交和分数在 PostgreSQL。启动时将数据库内残留的 `active` 比赛标为 `interrupted`。中断场次保留历史，不进入排行榜，玩家可重新开局。账号主界面通过 `/me/active` 查询正在进行的比赛，有比赛时禁用开始按钮并显示继续按钮。

完成的比赛快照在内存保留约一小时，之后从持久化结果接口读取。服务端上限 100 个同时活跃比赛、200 个房间只是资源保护阈值，不代表经过压测的容量承诺。

## 素材和公平性

生成模型与 SVG 描摹完全离线。导入器先验证四档文件，再事务发布同一变体版本。SVG 是静态图像资源，不承担运行时逻辑。Raw 原图另做背景预览，按用户要求公开用于启动页与资料面板；转换前的 HD/IN/AT PNG 不公开。

房间与练习开局时确定题组，不对客户端暴露未来题目或素材 ID。每日挑战已移除，历史数据库表只作存档保留。

正式计时开始后才允许下载当前题图，避免预加载提前看图；因此不同网络的图片加载时间仍会影响体验。速度奖励采用整秒分档，但这不等于竞技级网络公平。后续若做严肃排位，需要重新设计计时与加载规则，并使用真实 NAT 网络实测。

排行榜比较相同模式、开局难度、题数、时限和规则版本下的个人最佳完成记录，同分同名次。规则版本为 `v2-timed`，旧规则成绩不混入新榜。所有人猜中或倒计时结束才结束回合；错误尝试只记录，不结束机会。血条及扣血规则尚未实现。

## 当前产品范围

- 游客会话用于打通流程；正式账号注册、找回、第三方登录尚未实现。游客可以创建新身份，尚不具备防多账号刷榜能力。
- 已有视频参考驱动的前端、界面转场、可选的短提示音和用户提供的实际曲库；没有管理员网页、匹配系统、赛季段位或聊天。
- 没有在线模型调用、服务器描摹、自动难度评估或原图揭晓；目前揭晓曲名，原图揭晓可后续增加独立授权接口。
- SVG 校验采用严格子集；文件中的 id 仍需由素材审核保证不包含答案。自动描摹效果和真实难度需要人工验收。
- 日志记录基础服务错误；尚无外部监控告警、自动备份平台或生产负载基线。

## 前端接入

`apps/web` 使用 React + Vite，复用 `packages/contracts`。HTTP 负责操作，Socket.IO 负责完整状态快照；每 10 秒补取快照以处理遗漏，重连重新订阅。动画系统独立于比赛状态，即使降低动效或手机掉帧也不影响计分。

单人入口与“开始挑战”先进入 `/difficulty`，旧的账号页四按钮选择器已移除。`DifficultySelect` 用原生按钮提供选择与键盘访问，`DifficultyPainter` 在 Canvas 内重绘发光标签、双列汉字转轮、条带拖影和故障闪烁；GSAP 驱动连续时钟，绘制更新上限为 120fps，反相与故障帧仍对齐原片的 30fps 帧点。AT/IN/HD/EZ 的大数字改为“外挂/龙比/人类/区区”，使用 85,372 字节的 Heavy 汉字子集。

滚动字符池有 270 个不同汉字；每次进入生成独立随机种子，按列与行确定字符，使相邻文字连续接续，而非逐帧替换整列。左右滚动曲线分别按参考片拟合，右列更快。字形、柔光、连续纵向模糊与末段条带在 `difficulty-atlas.ts` 中一次缓存；后续帧仅组合纹理，跳过画外与不可见行，不实时描字或使用 Canvas filter。强模糊阶段先在每列的小缓冲中合成，再绘制到主画布；主画布像素数上限为 1920×1080，DPR 上限 1.5。

逐帧校准数据为 `difficulty-reference.json`。大字从参考第 75 帧进入，取消原先提前到 2.15 秒、持续 0.95 秒的估计放大；仅第 75～82 帧使用原片测得的短暂投影比例，之后保持稳定字号。入场位置来自可辨认帧的模板匹配，闪烁遮挡的间隙插值补齐；第 167～280 帧的左右上移量来自逐帧相关跟踪。第 280 帧之后强拖影中的速度仍使用尾段锚点，不能把该阶段声称为精确速度测量。

小字入口使用用户四段视频提取的透明图集 `public/difficulty/labels-*.webp`，覆盖第 15～110 帧的退场、居中与括号分离；之后的位置和透明度由原片小字跟踪结果驱动。图集一次加载并缓存，普通移动帧间混合更新，进入整屏闪帧时保持原片切换时刻。图集构建工具为 `tools/package-difficulty-motion.py`，测量与开发对照工具位于 `tools/measure-difficulty-*.py`、`tools/difficulty-frame-review.html`。

选择后播放约 14.7 秒的有效动画（参考片 0.5～15.2 秒），最终黑场才创建比赛，保证完整的准备与答题时限。返回或 Esc 取消不创建比赛；在减少动态效果模式下跳过滚动与闪烁。创建房间同样先选择难度，再提交房间参数；按房间码加入的流程不变。

启动页直接进入账号主界面，顶部导航为“游戏 / 排行榜 / 设置”。“游戏”合并玩家资料、模式选择与挑战设置，资料仍通过卡片的编辑按钮操作。游戏采用课题模式选曲布局：左侧为题目轨道，右侧为题图；难度只显示当前图片档位，灰条输入歌名，Select 位置提交。文字输入框聚焦时不显示蓝色外框，歌名框仅保留淡色下划线。提示直接显示在方框内，依次为章节范围、降低一档图片、章节与曲师；EZ 去掉降级项，只保留两个框。左侧由当前玩家自己的作答进度驱动，不暴露其他玩家的输入。

`HintStrip` 为纯展示组件：只能通过左上角“提示”按顺序解锁，框内没有按钮或点击处理。未解锁时仅显示 1st/2nd/3rd，解锁后只显示提示内容，没有编号、辅助小字和滚动条；内容根据框内空间换行、适配字号。

SVG 用 Bearer 请求后创建 Blob URL，保留相邻两张完成上下换图，释放旧 URL。新回合计时开始前不预取下一题；图片解码后才同步触发列表位移与曲绘运动。真实加载耗时仍会影响看到题图的时刻。

题图以 `object-fit: cover` 保持原比例铺满斜切框，边缘按框裁切。点击曲绘可在浏览器中央查看完整放大图，复用已授权的同一 Blob URL；Esc、关闭按钮或点击空白处返回。查看期间不暂停比赛，换题或图像难度变化会关闭查看层。原生 dialog 管理焦点与键盘退出。

猜歌页曲绘与作答区域保留原版构成，由 `game-alignment.css` 校准斜边；左侧整栏单独重写为 `SongRail.tsx` / `song-rail.css`，不再使用旧 `.track-*` 样式。曲绘切角按高度乘 tan(15°) 计算，输入栏、提示栏沿同一组斜线延伸。提示仍直接显示在框内，EZ 两提示、限时多次回答与计分规则保留；仅首题保留准备倒计时。

歌曲列表仅渲染本局题目。整栏共享 640×834 的局部坐标，工具栏与列表一起响应窗口宽度。背景平面、选中黑条与白块用独立 SVG 多边形绘制，文字用正直 HTML 排列：背景顶边从 x=193 延伸到 613.75，15% 黑色遮罩；选中条遮罩为 54%，不再让整栏变成深黑渐变。普通行 64px 节距，选中条高 90.5px，白块高 99px，上/下突出 4.5/4px。相邻上/下行额外让出 10.25/13.25px，沿 15° 轨道平滑移动。选中歌名 34.5px、普通歌名 22.5px；保留猜歌序号，不复制成绩标识。恢复挑战直接定位当前题。

未知歌名以 40ms 间隔更新与答案无关的字母、数字、符号和方块，文字区域尺寸固定；页面隐藏或减少动态效果时暂停。`SongName` 在答对后冻结乱码，以 220ms 非线性长条从左向右覆盖，完全覆盖时替换成真实曲名，再用 200ms 从左向右收拢到曲名末尾。已揭示曲名保持稳定，比赛时限与快速换题不受动画控制。

游戏、房间和结算共用的右上玩家框采用 `player-chip.css`：只裁切背景形状，头像和昵称不做斜切变换，并留出右边距。长昵称省略显示，上传头像以正方形区域正常渲染，避免父子反斜切叠加后被整个外框截断。

启动页和账号资料面板共用一次刷新随机选择的 Raw 原图预览，刷新时排除上一次图片。背景选择不影响题目抽样，也不返回歌名。题图降级独立记录在玩家与回合上，图片接口只返回该玩家解锁到的版本，重连可恢复。

账号界面只绘制一张铺满页面的背景图，并只保留一张斜切资料卡，包含可上传头像、昵称、玩家 ID、编辑与登出。资料卡内不再显示成绩统计，也不为此请求历史成绩接口；排行榜和比赛结算仍保留。卡外采用模糊与压暗遮罩，卡内是遮罩上的清晰窗口，透出同一背景对应区域，不单独铺图。窗口裁切随资料卡与窗口尺寸更新。

模式选择与挑战参数位于资料卡下方的两列区域，窄竖屏改为纵向排列。继续按钮仍在开始按钮下方；有进行中挑战时开始按钮禁用。账号页专用样式位于 `apps/web/src/account.css`，避免影响猜图界面。

同一歌曲可有多个 `variant`。题目抽样先按 `song_id` 分组，每组挑一个曲绘版本，再选本局歌曲。所有曲绘版本共享标准曲名与别名，不将同一首歌的四种原曲绘当作四首歌。
